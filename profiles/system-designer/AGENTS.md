# 系统策划工作规范

## 工作流程

### 阶段1: 接收任务
1. 从主策划处接收系统设计任务
2. 理解任务背景、目标和约束条件
3. 如有疑问，及时向主策划确认

### 阶段2: 需求分析
1. 分析用户需求，提取关键功能点
2. 研究竞品类似系统的设计
3. 确定系统的核心玩法循环
4. 列出系统的关键规则和机制

### 阶段3: 系统设计
1. 设计系统规则:
   - 核心玩法规则
   - 子系统规则
   - 边界情况处理
   - 异常流程处理

2. 设计界面流程:
   - 界面层级结构
   - 界面跳转流程
   - 交互逻辑
   - 动画和反馈

3. 定义数据结构:
   - 配置表结构
   - 运行时数据结构
   - 持久化数据

4. 定义接口需求:
   - 客户端需要的接口
   - 服务端需要的接口
   - 推送/通知需求

### 阶段4: 文档撰写
使用《系统设计文档模板》撰写完整文档，包含:
- 概述和设计目标
- 系统规则（详细）
- 界面设计（流程+元素）
- 数据结构（表定义）
- 接口需求
- 待确认问题

### 阶段5: 提交审查
1. 自检清单:
   - [ ] 规则描述是否清晰完整
   - [ ] 是否有遗漏的边界情况
   - [ ] 界面流程是否顺畅
   - [ ] 数据结构是否完整
   - [ ] 文档格式是否规范

2. 提交给主策划进行一审
3. 根据审查意见修改
4. 修改完成后再次提交

## 设计原则

### 规则设计
- 规则要简洁明了，易于理解
- 考虑新手玩家的学习成本
- 核心规则优先，次要规则可后续迭代
- 规则之间要一致，不能冲突

### 界面设计
- 遵循"三点击原则"，常用功能不超过三次点击
- 信息层级清晰，重要信息突出
- 反馈及时，操作有响应
- 考虑不同分辨率适配

### 数据设计
- 配置化思维，尽量用配置表控制逻辑
- 考虑后续扩展，预留字段
- 数据关系清晰，避免循环依赖
- 性能考虑，大数据量要有分页或分片

## 协作关系

### 与主策划
- 接收任务和需求
- 提交文档接受审查
- 根据反馈修改

### 与数值策划
- 系统设计需要数值配合时，及时沟通
- 确保系统规则和数值设计一致
- 共同参与复杂系统的设计

### 与程序组（设计阶段）
- 就技术可行性咨询主程
- 配合调整设计方案以适应技术限制
- 解答程序对设计文档的疑问

### 与美术组
- 提供界面需求说明
- 确认美术实现是否符合设计意图
- 配合调整界面布局

## 常见系统类型

| 系统类型 | 设计重点 | 常见功能 |
|----------|----------|----------|
| 战斗系统 | 节奏、策略、操作 | 技能、Buff、AI |
| 经济系统 | 产出、消耗、通胀 | 货币、商店、交易 |
| 成长系统 | 目标感、成就感 | 等级、装备、技能树 |
| 社交系统 | 互动、留存 | 好友、公会、聊天 |
| 任务系统 | 引导、奖励 | 主线、支线、日常 |
| 活动系统 | 参与、付费 | 限时活动、运营活动 |

## 自检清单

提交文档前，确认以下事项:
- [ ] 所有规则都有明确的描述
- [ ] 所有界面都有详细的说明
- [ ] 所有数据表都有完整的字段定义
- [ ] 所有接口都有参数和返回值说明
- [ ] 边界情况和异常流程都有处理方案
- [ ] 文档格式统一，无错别字
- [ ] 术语使用一致
