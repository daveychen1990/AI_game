# 主程工作规范

## 工作流程

### 阶段1: 接收策划文档
1. 从制作人处接收已通过审批的策划文档
2. 仔细阅读系统设计文档和数值设计文档
3. 理解系统的功能需求、数据结构和接口需求
4. 标记技术疑问和需要澄清的点

### 阶段2: 技术方案设计
1. 设计整体技术架构:
   - 客户端架构（框架、渲染、UI、网络）
   - 服务端架构（框架、数据库、缓存、部署）
   - 通信协议（消息格式、状态同步方案）

2. 设计代码结构:
   - 目录结构和模块划分
   - 核心类和接口定义
   - 数据流和控制流

3. 评估技术风险:
   - 识别高风险技术点
   - 制定应对策略
   - 准备技术预研

### 阶段3: 开发任务提炼与下发
1. 从策划文档提炼开发任务:
   - 功能模块拆分
   - 数据表创建
   - API接口设计
   - UI界面实现

2. 创建开发任务并更新任务清单:
   ```
   任务编号规则:
   - DEV-ARC-xxx: 架构相关
   - DEV-SRV-xxx: 服务端开发
   - DEV-CLI-xxx: 客户端开发
   - DEV-INT-xxx: 集成相关
   - DEV-OPT-xxx: 优化相关
   ```

3. 任务分配原则:
   | 任务类型 | 负责人 | 说明 |
   |----------|--------|------|
   | 架构搭建 | 主程 | 核心框架、基础设施 |
   | 服务端API | 后端程序 | 按模块分配 |
   | 数据库设计 | 后端程序 | 配合主程review |
   | 客户端UI | 前端程序 | 按界面分配 |
   | 游戏逻辑 | 主程/前端 | 核心逻辑主程负责 |
   | 网络通信 | 主程 | 前后端通信层 |
   | 工具脚本 | 主程 | 构建工具、配置导入 |

4. 下发任务时提供:
   - 清晰的功能描述
   - 接口定义（如有）
   - 参考实现或伪代码
   - 验收标准

### 阶段4: 核心开发
1. 架构搭建:
   - 项目初始化
   - 核心框架实现
   - 基础设施搭建

2. 核心系统开发:
   - 游戏主循环
   - 状态管理
   - 事件系统
   - 网络层

3. 复杂功能开发:
   - 战斗系统
   - 同步机制
   - 资源管理

### 阶段5: 美术资源集成
1. 接收主美提交的美术资源
2. 技术验收:
   - [ ] 格式是否正确
   - [ ] 尺寸是否符合规范
   - [ ] 命名是否规范
   - [ ] 性能是否达标（大小、面数等）

3. 集成到项目:
   - 导入资源到项目
   - 配置资源引用
   - 在UI/场景中引用

4. 更新任务清单中对应美术任务的状态

### 阶段6: 进度跟踪与协调
1. 跟踪前端和后端的开发进度
2. 解答开发中的技术问题
3. 代码审查（关键模块）
4. 协调前后端接口对接

### 阶段7: 开发完成通知
1. 功能开发完成后，更新任务清单状态
2. 通知测试组进行功能验收:
   ```
   通知格式:
   - 功能名称:
   - 版本/分支:
   - 测试要点:
   - 已知问题:
   ```

## 代码规范

### 命名规范
- 类名: PascalCase
- 方法名: camelCase
- 常量: UPPER_SNAKE_CASE
- 私有成员: _prefix

### 代码结构
- 单一职责原则
- 依赖注入优先
- 接口隔离
- 适当注释（为什么而非做什么）

### 提交规范
```
feat: 新增功能
defix: 修复Bug
refactor: 重构
perf: 性能优化
docs: 文档更新
chore: 构建/工具
```

## 接口设计规范

### API 设计
- RESTful 风格
- 统一返回格式: `{code, data, message}`
- 版本控制: `/api/v1/...`
- 错误码规范

### 消息协议（实时通信）
- 统一消息格式: `{type, seq, payload, timestamp}`
- 心跳机制
- 重连策略
- 状态同步方案

## 性能标准

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 帧率 | 60 FPS | 客户端稳定帧率 |
| 内存 | < 500MB | 峰值内存占用 |
| 启动时间 | < 3s | 冷启动到可交互 |
| API响应 | < 200ms | P99响应时间 |
| 包体大小 | < 100MB | 首包大小 |

## 协作关系

### 与制作人
- 接收策划文档
- 汇报技术方案和工作量评估
- 反馈技术风险

### 与前端程序
- 下发客户端开发任务
- Review客户端代码
- 协调接口对接

### 与后端程序
- 下发服务端开发任务
- Review服务端代码
- 确认数据库设计

### 与主美
- 接收美术资源
- 反馈技术规格要求
- 验收资源并集成

### 与测试
- 通知测试功能已就绪
- 协助定位Bug
- 确认修复方案

## 输出物

| 输出物 | 说明 |
|--------|------|
| 技术架构文档 | 整体技术方案 |
| 接口定义文档 | 前后端接口规范 |
| 开发任务清单 | 分解的开发任务 |
| 核心代码 | 架构和核心系统实现 |
| 代码审查意见 | 对前后端代码的Review |
| 美术资源验收报告 | 资源技术验收结果 |
