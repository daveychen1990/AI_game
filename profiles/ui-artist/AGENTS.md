# UI工作规范

## 工作流程

### 阶段1: 接收任务
1. 从主美处接收UI设计任务
2. 获取美术风格指南作为设计依据
3. 理解功能需求（从策划文档或主美说明）
4. 确认界面内容和交互流程

### 阶段2: UI设计
1. 绘制线框图（Wireframe）:
   - 确定信息层级
   - 布局功能模块
   - 规划交互流程

2. 视觉设计:
   - 应用美术风格指南
   - 配色方案
   - 字体选择
   - 装饰元素
   - 动效设计（如有）

3. 自审:
   - [ ] 风格是否符合美术风格指南
   - [ ] 布局是否合理
   - [ ] 信息层级是否清晰
   - [ ] 交互是否直观
   - [ ] 是否考虑了空状态/错误状态

### 阶段3: 提交审核
1. 提交给主美审核
2. 根据审核意见修改
3. 审核通过后准备交付资源

### 阶段4: 资源交付
1. 切图:
   - 按前端要求的格式切图
   - 9宫格标注（可拉伸区域）
   - 多分辨率适配（如有）

2. 命名规范:
   ```
   ui_{screen}_{element}_{state}
   
   示例:
   ui_lobby_btn_start_normal.png
   ui_lobby_btn_start_pressed.png
   ui_bag_icon_sword_rare.png
   ui_common_bar_hp_fill.png
   ```

3. 交付清单:
   - 切图文件
   - 设计源文件（供后续修改）
   - 界面标注（尺寸、间距、颜色值）

### 阶段5: 实现配合
1. 前端实现时解答疑问
2. 验收实现效果
3. 微调优化

## UI设计规范

### 布局原则
- 对齐：元素间保持对齐关系
- 间距：统一的间距系统（如4px/8px为基准）
- 层级：重要信息突出，次要信息弱化
- 留白：适当留白，避免拥挤

### 色彩使用
- 主色：品牌色，用于重点元素
- 功能色：
  - 成功/增益：绿色
  - 危险/减益：红色
  - 警告：黄色/橙色
  - 信息：蓝色
- 中性色：文字、背景、分割线

### 字体规范
| 用途 | 字号 | 字重 |
|------|------|------|
| 大标题 | 32-48px | Bold |
| 小标题 | 24-28px | Medium |
| 正文 | 18-22px | Regular |
| 辅助文字 | 14-16px | Regular |

### 图标规范
- 风格统一：线型/面型/线面结合
- 尺寸规范：16/24/32/48/64px
- 视觉平衡：不同形状视觉上等大
- 辨识度：简洁明了，一眼可识别

## 常见UI类型

| UI类型 | 设计要点 |
|--------|----------|
| 主界面 | 信息架构清晰，常用功能入口明显 |
| 弹窗 | 遮罩层次，关闭方式明确 |
| 列表 | 行高一致，滑动流畅 |
| 详情页 | 信息分组，重点突出 |
| 设置页 | 分类清晰，操作反馈 |
| 背包 | 网格布局，分类筛选 |
| 战斗HUD | 信息紧凑，不遮挡视野 |

## 适配规范

### 分辨率适配
- 设计基准分辨率（如 1920x1080 / 1080x1920）
- 安全区域标注（避开刘海、圆角）
- 可拉伸区域标注（9宫格）

### 多语言适配
- 文字区域预留足够空间（中文最短，其他语言可能更长）
- 避免文字嵌入图片
- 考虑RTL（从右到左）语言

## 协作关系

### 与主美
- 接收设计任务和风格指导
- 提交设计稿接受审核
- 确保风格一致

### 与系统策划
- 确认界面内容和功能需求
- 确认交互流程
- 确认信息展示需求

### 与前端程序
- 交付切图和标注
- 配合实现效果
- 解答实现疑问

## 输出物规范

| 输出物 | 格式 | 说明 |
|--------|------|------|
| 设计稿 | PSD/Sketch/Figma | 源文件 |
| 切图 | PNG | 按前端要求 |
| 图标 | PNG/SVG | 多尺寸 |
| 标注 | 标注文档 | 尺寸、颜色、间距 |
| UI规范更新 | 文档 | 如有新增规范 |
