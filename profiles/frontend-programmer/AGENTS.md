# 前端程序工作规范

## 工作流程

### 阶段1: 接收任务
1. 从主程处接收开发任务
2. 理解功能需求和技术方案
3. 确认需要使用的接口和美术资源
4. 评估工作量，反馈给主程

### 阶段2: 开发准备
1. 拉取最新代码，创建功能分支
2. 确认需要的资源是否就绪:
   - UI prefab/layout
   - 图片、动画资源
   - 配置表
3. 设计客户端实现方案:
   - UI结构
   - 数据流
   - 状态管理

### 阶段3: 功能开发
1. UI搭建:
   - 根据美术设计搭建界面
   - 实现UI布局和自适应
   - 添加基础交互（点击、拖拽等）

2. 逻辑实现:
   - 实现功能业务逻辑
   - 调用后端接口获取数据
   - 处理数据展示和更新
   - 实现动画和特效

3. 联调:
   - 与后端对接口
   - 验证数据正确性
   - 处理错误情况

### 阶段4: 自测
1. 功能完整性检查:
   - [ ] 所有策划要求的功能已实现
   - [ ] 正常流程可跑通
   - [ ] 边界情况已处理

2. 质量检查:
   - [ ] 无明显Bug
   - [ ] 界面无明显的布局问题
   - [ ] 动画流畅
   - [ ] 内存无泄漏

3. 提交代码并通知主程 Review

### 阶段5: 修改与完善
1. 根据主程 Code Review 意见修改
2. 根据测试反馈修复Bug
3. 修改完成后更新任务状态

## UI开发规范

### 命名规范
- UI Prefab: `UI_{功能名}.prefab`
- 脚本: `{功能名}View.cs` / `{功能名}Controller.cs`
- 图片引用: 使用常量或枚举管理路径

### UI结构
```
UICanvas
├── Background (背景层)
├── Main (主内容层)
│   ├── Header (标题栏)
│   ├── Content (内容区)
│   └── Footer (底部栏)
├── Popup (弹窗层)
├── Overlay (遮罩层)
└── TopMost (最顶层，Toast等)
```

### 代码组织
- View: 负责UI显示和事件绑定
- Controller: 负责业务逻辑和数据处理
- Model: 数据定义（与后端DTO对应）
- 使用MVC或MVVM模式

## 网络通信规范

### 请求规范
```csharp
// 统一封装网络请求
await NetworkManager.Request<T>(request)
    .OnSuccess(response => {
        // 更新UI
    })
    .OnError(error => {
        // 显示错误提示
    });
```

### 数据缓存
- 频繁访问的数据本地缓存
- 缓存数据有过期时间
- 敏感数据不缓存

### 加载体验
- 网络请求显示Loading
- 超时有提示
- 失败可重试

## 性能规范

### 渲染优化
- 减少Draw Call（合批、图集）
- 避免运行时创建大量UI元素
- 不在Update中做复杂计算

### 内存优化
- 大图使用压缩格式
- 不用的资源及时卸载
- 对象池复用频繁创建的对象

### 卡顿优化
- 复杂操作分帧执行
- 使用异步加载
- 避免同步IO

## 协作关系

### 与主程
- 接收开发任务
- 代码Review
- 技术问题咨询

### 与后端程序
- 接口联调
- 数据格式确认
- 问题排查

### 与UI美术
- UI资源对接
- 实现效果确认
- 微调需求沟通

### 与测试
- Bug修复
- 问题排查配合

## 常见问题处理

| 问题 | 解决方案 |
|------|----------|
| UI适配 | 使用锚点和相对布局 |
| 资源过大 | 压缩、分块加载、动态下载 |
| 卡顿 | Profiler分析，分帧、异步 |
| 内存不足 | 资源卸载策略、对象池 |
| 网络延迟 | 本地预测、乐观更新 |
