# 数值策划工作规范

## 工作流程

### 阶段1: 接收任务
1. 从主策划处接收数值设计任务
2. 理解系统的数值需求和设计目标
3. 确认数值设计的约束条件（如付费深度、游戏时长等）

### 阶段2: 数值框架设计
1. 确定数值体系的核心参数
2. 设计核心计算公式:
   - 战斗公式（伤害、防御、暴击等）
   - 成长公式（经验、属性成长）
   - 经济公式（产出、消耗、回收）

3. 设计数值曲线:
   - 成长曲线（等级→属性）
   - 难度曲线（进度→挑战）
   - 经济曲线（时间→资源）

### 阶段3: 数值建模
1. 使用 Excel 搭建数值模型:
   - 创建参数表
   - 建立公式关联
   - 生成数值曲线
   - 模拟玩家成长路径

2. 常见 Sheet 结构:
   ```
   - 参数表: 所有可调参数集中管理
   - 等级表: 等级与属性的对应关系
   - 战斗表: 伤害计算和平衡验证
   - 经济表: 资源产出和消耗
   - 装备表: 装备属性设计
   - 验证表: 测试用例和结果
   ```

### 阶段4: 平衡性验证
1. 设计测试用例:
   - 正常情况验证
   - 极端情况验证（满级、最低配）
   - 边缘情况验证（临界值）

2. 模拟验证:
   - 模拟不同玩家类型的成长路径
   - 验证经济系统长期稳定性
   - 检查是否存在数值崩坏风险

3. 输出验证报告:
   - 测试用例和结果
   - 发现的问题和建议

### 阶段5: 文档撰写
使用《数值设计文档模板》撰写文档，包含:
- 设计原则和思路
- 核心公式（附推导过程）
- 参数表（含可调范围）
- 数值曲线图
- 平衡性验证结果

### 阶段6: 提交审查
1. 提交给主策划进行一审
2. 根据审查意见修改
3. 修改完成后再次提交

## 数值设计方法

### 战斗数值设计
1. 确定战斗节奏（几场战斗升级、战斗时长）
2. 设计基础属性（HP、ATK、DEF等）
3. 设计战斗公式:
   - 伤害公式: `Damage = ATK * skill_multiplier - DEF * mitigation_rate`
   - 暴击公式: `Crit Damage = Damage * (1.5 + crit_bonus)`
   - 命中公式: `Hit Rate = base_hit + accuracy - evasion`

4. 验证战斗平衡:
   - 同级战斗时长
   - 越级战斗惩罚
   - 不同build的差异

### 经济系统设计
1. 确定经济目标（控制通胀、促进付费）
2. 设计货币体系:
   - 软货币（游戏币）：大量产出，大量消耗
   - 硬货币（钻石）：稀缺，用于付费
   - 代币（活动币）：限时产出和消耗

3. 设计产出和消耗:
   - 日常产出 = 日常消耗 + 储蓄（少量）
   - 防止通胀：设置回收机制
   - 付费点设计：硬货币的关键使用场景

4. 验证经济健康度:
   - 模拟30天资源积累
   - 检查是否有无限套利
   - 验证付费深度是否合理

### 成长曲线设计
1. 确定总成长空间（等级上限、属性上限）
2. 选择曲线类型:
   - 线性: 匀速成长
   - 指数: 前期快后期慢
   - 对数: 前期慢后期快
   - S型: 中间快两头慢

3. 设计经验表:
   - 每级所需经验递增
   - 总时长控制在目标范围内
   - 关键节点有质的变化

## 协作关系

### 与主策划
- 接收数值设计任务
- 提交数值文档接受审查
- 根据反馈调整数值

### 与系统策划
- 配合系统设计进行数值实现
- 确保数值表达设计意图
- 复杂系统需要联合设计

### 与程序组
- 提供数值配置表
- 确认公式实现是否正确
- 配合进行数值调优

## 常见数值问题及解决

| 问题 | 现象 | 解决方案 |
|------|------|----------|
| 数值膨胀 | 后期数值过大 | 使用分段曲线或压缩公式 |
| 经济通胀 | 货币贬值 | 增加回收机制，控制产出 |
| 平衡崩坏 | 某一策略过强 | 引入克制关系，调整收益 |
| 成长停滞 | 玩家感觉不到成长 | 调整曲线斜率，增加里程碑 |
| 付费失衡 | 免费和付费差距过大 | 设计付费效率递减 |

## 输出物规范

### Excel 表格规范
- 使用明确的颜色标记（输入/公式/输出）
- 添加注释说明复杂公式
- 使用命名区域便于引用
- 添加版本号和修改记录

### 数值文档规范
- 所有公式有推导过程
- 所有参数有默认值和可调范围
- 所有曲线有图表说明
- 验证结果有数据支撑
