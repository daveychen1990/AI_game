# 测试工作规范

## 工作流程

### 阶段1: 接收测试通知
1. 从主程处接收功能测试通知:
   ```
   通知格式:
   - 功能名称: xxx系统
   - 版本/分支: dev/xxx
   - 测试要点: 核心功能点
   - 已知问题: 已知的Bug或限制
   ```

2. 从任务清单中确认待测试任务
3. 阅读相关策划文档，了解预期行为

### 阶段2: 测试准备
1. 准备测试环境:
   - 确认测试版本
   - 准备测试数据
   - 确认测试设备/平台

2. 制定测试计划:
   - 列出测试点
   - 设计测试用例
   - 确定测试优先级

### 阶段3: 执行测试

#### 功能测试
按照策划文档验证:
- [ ] 所有功能点是否实现
- [ ] 功能逻辑是否正确
- [ ] 数据计算是否准确
- [ ] 异常处理是否完善

#### 界面测试
- [ ] UI布局是否正确
- [ ] 文字显示是否完整
- [ ] 图片/资源是否显示正常
- [ ] 动画效果是否正常
- [ ] 不同分辨率适配

#### 流程测试
- [ ] 正常流程是否通畅
- [ ] 逆向流程是否正确（如返回、取消）
- [ ] 多步骤流程中间中断的处理
- [ ] 并发操作的处理

#### 边界测试
- [ ] 空值/零值处理
- [ ] 最大值/最小值
- [ ] 超长输入
- [ ] 快速连续操作
- [ ] 网络异常时的表现

### 阶段4: Bug记录
发现Bug时，使用以下格式记录:

```markdown
## Bug报告

### 基本信息
- Bug编号: BUG-{序号}
- 发现人: {测试人员}
- 发现日期: {日期}
- 严重程度: [致命/严重/一般/轻微]
  - 致命: 导致崩溃、数据丢失、无法继续游戏
  - 严重: 核心功能无法使用、严重体验问题
  - 一般: 功能可用但有问题、非核心功能缺陷
  - 轻微: 显示问题、不影响功能的小问题
- 优先级: [高/中/低]

### 环境信息
- 版本: {版本号}
- 平台: [PC/iOS/Android/其他]
- 设备: {设备型号}
- 网络: [WiFi/4G/5G]

### 复现步骤
1. {步骤1}
2. {步骤2}
3. {步骤3}
{预期结果: 应该发生什么}
{实际结果: 实际发生了什么}

### 截图/录屏
{附件}

### 备注
{其他信息}
```

### 阶段5: 测试报告
测试完成后，输出测试报告:

```markdown
# 测试报告

## 基本信息
- 功能名称:
- 测试版本:
- 测试时间:
- 测试人:

## 测试概要
- 测试用例数:
- 通过:
- 失败:
- 阻塞:

## Bug统计
| 严重程度 | 数量 |
|----------|------|
| 致命 | x |
| 严重 | x |
| 一般 | x |
| 轻微 | x |

## Bug清单
| 编号 | 描述 | 严重程度 | 状态 |
|------|------|----------|------|
| BUG-001 | xxx | 严重 | 待修复 |

## 测试结论
- [ ] 通过（无严重Bug，可验收）
- [ ] 有条件通过（有小问题不影响主线）
- [ ] 不通过（有严重Bug需修复）

## 风险说明
{如有风险，说明影响和应对}

## 建议
{优化建议}
```

### 阶段6: 结果反馈
1. 将测试报告反馈给制作人
2. 更新任务清单状态:
   - 通过: 标记为"已完成"
   - 不通过: 标记为"已打回"，附Bug报告
3. 等待Bug修复后重新验证

## 测试用例设计

### 用例模板
```
用例编号: TC-{模块}-{序号}
用例名称: {简要描述}
前置条件: {测试前需要准备的条件}
测试步骤:
  1. {步骤}
  2. {步骤}
预期结果: {应该出现的结果}
优先级: [高/中/低]
```

### 用例设计方法
1. 等价类划分: 将输入分为有效和无效等价类
2. 边界值分析: 测试边界值和边界附近值
3. 场景法: 模拟用户实际使用场景
4. 错误推测: 根据经验推测容易出错的地方
5. 正交实验: 多因素组合测试

## Bug严重程度定义

| 级别 | 定义 | 示例 |
|------|------|------|
| 致命 | 导致程序崩溃、数据损坏、无法继续 | 游戏闪退、存档丢失 |
| 严重 | 核心功能无法使用、严重影响体验 | 无法登录、关键功能失效 |
| 一般 | 功能可用但有问题、非核心功能缺陷 | 显示错误、次要功能异常 |
| 轻微 | 显示瑕疵、不影响功能 | 文字错别字、轻微对齐问题 |

## 协作关系

### 与主程
- 接收测试通知
- 反馈测试结果
- 协助定位Bug

### 与前端/后端程序
- 报告Bug，提供复现信息
- 验证Bug修复
- 确认实现是否符合预期

### 与制作人
- 汇报测试结果
- 提出上线建议
- 反馈质量风险

### 与策划
- 确认功能预期行为
- 反馈设计体验问题
- 确认Bug是否为设计如此

## 注意事项

1. **客观公正**: 不因与开发者关系而放松标准
2. **详细记录**: Bug报告要详细，让开发者能复现
3. **及时反馈**: 发现问题及时记录和反馈
4. **版本管理**: 明确测试的是哪个版本
5. **环境一致**: 复现Bug时在相同环境下验证
6. **回归测试**: Bug修复后要验证是否引入新问题
