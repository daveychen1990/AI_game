# 后端程序工作规范

## 工作流程

### 阶段1: 接收任务
1. 从主程处接收开发任务
2. 理解功能需求和数据模型
3. 确认接口定义（由主程提供或共同制定）
4. 评估工作量，反馈给主程

### 阶段2: 数据库设计
1. 根据策划文档设计数据表:
   - 玩家数据表
   - 游戏数据表
   - 配置数据表
   - 日志数据表

2. 设计原则:
   - 表结构符合第三范式
   - 适当冗余以提高查询性能
   - 索引设计合理
   - 考虑分表分库扩展

3. 输出数据库设计文档

### 阶段3: API开发
1. 实现接口:
   - 按接口定义实现逻辑
   - 参数校验
   - 业务逻辑处理
   - 数据存取
   - 返回格式化

2. 接口类型:
   | 类型 | 用途 | 示例 |
   |------|------|------|
   | HTTP REST | 通用接口 | 登录、获取信息 |
   | WebSocket | 实时通信 | 战斗同步、聊天 |
   | RPC | 内部调用 | 服务间通信 |

3. 接口规范:
   ```json
   // 请求
   {
     "user_id": 10001,
     "item_id": 2001,
     "count": 5
   }

   // 成功响应
   {
     "code": 0,
     "data": { ... },
     "message": "success"
   }

   // 错误响应
   {
     "code": 1001,
     "data": null,
     "message": "Insufficient items"
   }
   ```

### 阶段4: 业务逻辑实现
1. 核心逻辑:
   - 玩家数据管理
   - 游戏逻辑计算
   - 奖励发放
   - 状态校验

2. 安全校验:
   - 参数合法性检查
   - 权限校验
   - 防作弊验证
   - 频率限制

3. 事务处理:
   - 关键操作使用事务
   - 异常时回滚
   - 幂等性设计

### 阶段5: 自测
1. 单元测试:
   - [ ] 正常流程测试
   - [ ] 边界条件测试
   - [ ] 异常情况测试
   - [ ] 并发测试（关键接口）

2. 接口测试:
   - [ ] 所有参数组合
   - [ ] 错误参数处理
   - [ ] 返回值格式正确

3. 提交代码并通知主程 Review

### 阶段6: 联调
1. 与前端程序对接:
   - 确认请求参数
   - 验证返回数据
   - 处理联调问题

2. 联调完成后更新任务状态

## 数据库规范

### 命名规范
- 表名: `t_{模块}_{实体}`，如 `t_player_base`
- 字段: 下划线命名，如 `player_id`
- 索引: `idx_{表名}_{字段}`

### 字段设计
- 每个表必须有 `id`, `created_at`, `updated_at`
- 使用合适的字段类型和长度
- 枚举值用 TINYINT，配注释说明
- 大文本用 TEXT，图片URL用 VARCHAR

### 索引设计
- 主键、外键自动索引
- 查询条件字段加索引
- 避免过多索引影响写入
- 联合索引注意字段顺序

## API设计规范

### URL设计
```
/api/v1/player/info      # 获取玩家信息
/api/v1/player/update    # 更新玩家信息
/api/v1/bag/items        # 获取背包物品
/api/v1/bag/use          # 使用物品
```

### 错误码规范
| 编码段 | 含义 |
|--------|------|
| 0 | 成功 |
| 1-99 | 通用错误 |
| 100-199 | 认证授权错误 |
| 200-299 | 玩家数据错误 |
| 300-399 | 游戏逻辑错误 |
| 400-499 | 系统错误 |

### 日志规范
- 请求日志: 记录请求参数和响应
- 错误日志: 记录异常堆栈
- 业务日志: 记录关键业务操作
- 性能日志: 记录耗时操作

## 性能规范

### 响应时间
| 接口类型 | P99目标 |
|----------|---------|
| 普通查询 | < 50ms |
| 复杂查询 | < 200ms |
| 写入操作 | < 100ms |

### 并发处理
- 使用连接池
- 热点数据加缓存
- 异步处理非关键操作
- 限流和熔断保护

## 协作关系

### 与主程
- 接收开发任务
- 技术方案确认
- 代码Review

### 与前端程序
- 接口联调
- 数据格式确认
- 问题排查

### 与策划
- 确认数据结构需求
- 逻辑实现确认
- 配置表格式确认

## 常见问题处理

| 问题 | 解决方案 |
|------|----------|
| 高并发 | 缓存、异步、限流、扩容 |
| 数据不一致 | 事务、锁、最终一致性 |
| 慢查询 | 索引优化、SQL优化、分表 |
| 内存不足 | 缓存策略调整、数据分片 |
| 服务宕机 | 健康检查、自动重启、降级 |
